# .maestro

- `.maestro/` holds [Maestro](https://docs.maestro.dev) flows driven by the mock login: log in and visit every tab, open a notice / assignment / file, favorite and archive, search, settings pages and logout. `.maestro/subflows/` is only reached through `runFlow`.
- Install the CLI with `brew install mobile-dev-inc/tap/maestro`; it runs on the JDK in `JAVA_HOME` (17+). Boot exactly one simulator or emulator (or set `MAESTRO_DEVICE=<udid or serial>`) and install the Release build with `scripts/e2e-build.sh ios <udid>` / `scripts/e2e-build.sh android <serial>`: E2E runs always use Release (bundled JS, R8 on Android), never a debug build with Metro. One iOS build installs on every simulator of the same architecture; rebuild after changing app code.
- CI (Android only): run Native (`.github/workflows/build.yml`) by hand with "Android E2E tests" ticked. That job installs the APK from "Android release build" (`-PciRelease`: R8 and the bundled JS, signed with the debug key, no Crashlytics uploads, mock login from a generated `.env`) in an API 36 emulator, runs every flow, and uploads Maestro's results with logcat. iOS E2E isn't in CI.
- `pnpm e2e:ios` / `pnpm e2e:android` run every flow; append a path to run one, e.g. `pnpm e2e:android .maestro/03_favorite_archive.yaml`. `scripts/e2e.sh` passes `APP_ID` (the bundle ids differ in case: `io.robertying.learnX` vs `io.robertying.learnx`) and the two mock values from `.env` with `-e`; never hard-code them in a flow.
- The flows share one login: `00_reset.yaml` clears the app first (`executionOrder` in `config.yaml` runs the flows in order and logs out last), and `subflows/login.yaml` relaunches the app with the `mockLatency: none` launch argument (no emulated server delay) and logs in only when the app shows the welcome or login page. A flow run alone starts from whatever the app shows, logged in or not. A flow that changes data (favorites, archives, filters) puts it back before it ends; a flow added outside `flowsOrder` runs after the logout and logs in again.
- Keep runs fast: a `when: visible` on an element that isn't there (or a `notVisible` on one that is), an `optional` tap that finds nothing and an `optional` `extendedWaitUntil` each wait out Maestro's lookup timeout (7 s, or the given timeout). Branch on what's known instead: `platform`, `true: ${IPAD == 'true'}` (`scripts/e2e.sh` sets `IPAD` on an iPad simulator), or `copyTextFrom` on the element that did show, as `subflows/login_form.yaml` does for the "Save Password?" alert some iOS devices show.
- Select by `testID` (`id:`) first; otherwise match the visible text or accessibility label in both languages, so the flows pass in English and Chinese. Never copy a label or mock text into a flow: `scripts/e2e-env.mjs` reads them from the translations and the mock data (which follows the app's language, `data/mockEnglish.ts`) and `scripts/e2e.sh` passes them with `-e`: `${T_<key>}` is translation `<key>` as `English|中文` (any key a flow names is passed), and `${MOCK_*}` are the mock items the flows open, listed in that script. Labels the app doesn't own (UIKit's page buttons, the Save Password sheet) are the only text written in flows. Regexes must match the whole label: iOS merges a card's texts into one label (`'Course, Title, …'`) and reads a header button's badge or a menu item's count after its label (`'Settings, New'`), so match content as `'.*(${MOCK_NOTICE}).*'` and such labels as `'(${T_settings})(, .*)?'`. `data/__tests__/mockE2e.test.ts` runs the script and checks that every value a flow uses has both languages.
- iOS quirks: after a `clearState` launch the native tab bar buttons lose their identifiers in Maestro's snapshot, so tabs are matched as `'tab-files|folder\.fill'` (testID or the filled SF Symbol from `filledSymbols` in `navigation/MainTab.tsx`; Today's follows the time of day, so its regex lists all four); the login subflow dismisses the "Save Password?" sheet; `hideKeyboard` is flaky, so tap something inert instead. iOS header buttons are native bar items and only expose their label. Text input is ASCII only: Maestro can't type CJK on Android, so search for ASCII mock content.
- Swipe actions are iOS only; Android opens the same actions from a long-press menu (`subflows/card_actions.yaml` handles both). iOS has no system back, so `subflows/back.yaml` swipes from the left edge, and skips it when the list is still on screen (iPad split view).
- The flows are kept passing on iPhone and the folded Android foldable, in both languages (switch the simulator with `simctl spawn <udid> defaults write -g AppleLanguages '("zh-Hans")'` and a reboot, the emulator app with `cmd locale set-app-locales`), and in the manual Android CI job. iPad and iPhone Duo (folded) passed before the Today and Settings changes and may have drifted. Maestro can't drive Mac Catalyst.

- iPad: set the simulator to Settings › Multitasking & Gestures › Full Screen Apps; with Windowed Apps Maestro only sees SpringBoard. The tabs sit in a paged top bar (`subflows/tab.yaml` turns the page) and details open beside the list.
- Postures: fold / unfold the Android foldable with `adb emu fold` / `adb emu unfold` (`adb shell cmd device_state state` shows the current one). The iPhone Duo hinge can only be changed by hand in the Simulator window.
- iPhone Duo screenshots need the display: `xcrun simctl io <udid> screenshot --display 1|3 <out.png>` (1 = outer, 3 = inner); the command can hang.
