# src/screens

How lists and detail screens open and show items, and what first launch shows. Navigators and headers are in `src/navigation/AGENTS.md`, the components screens are built from in `src/components/AGENTS.md`.

- Today keeps to what's on now and next (the class on now and the next one, what's due soon, unread counts), so a busy day doesn't push the rest off screen; the whole week is in Schedule. Settings opens from Today's header rather than as a tab, since Android's navigation bar holds at most five tabs and iPhone moves a sixth into "More". The Mac's sidebar and the Electron app's navigation pane keep it as a tab.
- First launch: a new install (`data/install`) first drops a login the iOS keychain kept from before the app was deleted, then shows Welcome. Once the main UI shows, `hooks/useLaunchSheet` opens at most one sheet, Setup after the first login or What's New for a newer release, and none when the app was opened from a notification, widget, link or Spotlight. What's New is keyed by `package.json`'s version, which over-the-air updates change too, so a row that needs new native code says so with `minNative`.
- Lists open an item with `useShowDetail` (`hooks/useDetailNavigator`): in a split view's detail pane, which starts over with the item, or pushed on the list otherwise. A screen that stacks something on its item in the pane uses `useDetailNavigator().push`; a page about the whole app (Search, CourseX from the Courses list) opens over the whole window from the root navigator instead. The content tabs share `hooks/useContentList`.
- Detail screens take `{ id }` params and read the item from the query cache, so they stay current after a refresh: pass the id, never the item. An item missing from the semester being shown is looked up in the other semesters' cached lists, so a detail screen left open survives a semester switch. They show `components/NotFound` when the item is gone. Attachments are not in the cache, so `FileDetail` also takes `{ attachment }`.
- `FileDetail` picks how to preview a file with `previewKind` (`helpers/filePreview`). The Mac's web view can't convert Office and iWork documents as iOS's does, so the Mac shows them with Quick Look (`modules/AGENTS.md`).
- Search ranks results by what needs attention as of when the query was typed, so a result opened and read keeps its place; a new query ranks afresh.
