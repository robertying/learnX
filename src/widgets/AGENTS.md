# src/widgets

- The "Deadlines" home screen widget (iOS and Android) is built with `expo-widgets`. Its layouts are `src/widgets/Deadlines.tsx` (`@expo/ui/swift-ui`) and `src/widgets/Deadlines.android.tsx` (`@expo/ui/jetpack-compose`, limited to what Glance supports). A function with the `'widget'` directive is turned into a string by the widgets Babel plugin (from babel-preset-expo) and runs in the widget runtime: no hooks, imports or outside values, only its props and `environment`. `src/widgets` is left out of the React Compiler.
- `updateDeadlineWidget` (`src/widgets`) is called by `services/surfaces` whenever the cached assignments, archives or hidden courses change (see "Surfaces" in the root `AGENTS.md`), and emptied on logout. On iOS it writes a timeline with an entry at each upcoming deadline and each time one turns orange or red (`deadlineChangeTimes`), so due items change color and drop off without the app; each deadline carries its `soonFrom` and `urgentFrom`, and the layouts color it by their own clock; Android gets a snapshot of up to ten deadlines with preformatted due times; `DeadlinesProvider` redraws every 30 minutes (`res/xml/deadlines_info.xml`) and the layout leaves out the ones that have passed by `Date.now()`.
- Taps: each row carries a `learnx://assignment/<id>` link and the widget a `learnx://assignment` one (`getTargetUrl` in `helpers/openTarget.ts`). `useLinkTaps` opens them through the same path as notification taps (see `src/navigation/AGENTS.md`); other `learnx://` links, like the share extension's, are ignored. iOS medium and large widgets wrap rows in `Link` and set `widgetURL` for the rest; small widgets have one tap target (the list) and the Lock Screen one opens the next assignment. Android rows use the `openUrl` modifier.
- iOS layouts share what they have in common through `widgets/kit.tsx`: `widgetKit` is a `'widget'` function too, so it becomes source text, and `withWidgetKit(layout)` (passed to `createWidget`) makes the source the widget runtime evaluates create the kit once and call the layout with it as a third argument. The kit has the `ViewThatFits` and `Countdown` elements of our expo-widgets patch (`ViewThatFitsView`, `CountdownView`; @expo/ui has neither, so it makes their nodes itself), the brand accent, deadline colors, section labels, the one-line "title · course · time left" and `fitted`. Layouts can't use what Babel compiles to helpers (array destructuring becomes `_slicedToArray`); a test checks the layouts' source for them.
- `fitted` lists as many rows as fit: one version of the list per row count in SwiftUI's `ViewThatFits`, which shows the first, the most rows, that fits the widget's height at its size and text size. A version that leaves rows out spreads the ones it shows over the height (a `Spacer` with the rows' spacing as its minimum before each), so the leftover space doesn't all end up at the bottom; one that shows every row keeps them at the top. Deadlines offers one version per count (each with its own `+N`); Up Next offers one per count of the classes after the featured one, a large one naming them above the first. A small Deadlines widget puts each course after its title ("Homework 6 · Course"), where it shortens first.
- iOS countdowns (deadline rows, Up Next's class, the Lock Screen widgets) use the kit's `Countdown` (our patch's `CountdownView`), not `Text` with `dateStyle="relative"`: on iOS 18 and later it shows the time left live in days, hours and minutes, at most two (`maxFieldCount`, 1 where only the largest unit fits), without the seconds the relative style counts under an hour; below iOS 18 it falls back to the relative style. It takes the width of its value at render time, so the text before it in a row (a course name) shortens first.
- We don't use prebuild, so the native setup the expo-widgets config plugin would generate is checked in: the `ExpoWidgetsTarget` extension (`ios/ExpoWidgetsTarget`, bundle id `io.robertying.learnX.Widgets`, app group `group.io.robertying.learnX`, iOS only, not on Mac Catalyst), its Podfile target, `ExpoWidgetsAppGroupIdentifier` in the app's Info.plist, and on Android `DeadlinesProvider`, its manifest receiver and `res/xml/deadlines_info.xml` / `res/values/expo_widgets.xml`. When upgrading expo-widgets, run its config plugin in a throwaway prebuild copy and compare. Adding a widget means a new Swift widget in `index.swift`, a provider on Android and an entry in `expo_widgets_names`.
- Android: the Gradle build embeds `Deadlines.android.tsx` and its `initialProps` (listed in `android/app/src/main/expo-widgets-layout-registry.config.json`), so a widget added before the app has run shows "Open learnX to see deadlines" instead of expo-widgets' "No layout found". The layout the app stores at runtime wins over the embedded one. Gradle doesn't track the layout file as an input, so a layout change may need a clean build to update the embedded copy. Our `expo-widgets` patch makes tapping anywhere on the widget open the app, adds an `openUrl` modifier (`{ $type: 'openUrl', url }`, a Glance `actionStartActivity` for an `ACTION_VIEW` intent) for per-row links, and adds `environment.locale`, since the embedded props can't hold translated strings.
- The "Up Next" widget (`src/widgets/UpNext.tsx`, `UpNext.android.tsx`, `updateUpNextWidget`) shows the class on now or next and the classes after it (no deadlines: the Deadlines widget has them, and its Chinese label 下一节课 names classes only). `services/surfaces` feeds it this week's and next week's classes from the cache (`getCachedWeekSessions` in `data/schedule`: Today's calendar or course-time fallback, without hidden courses); `useUpNext` (main UI) keeps those two weeks fetched. Its props hold all the classes still ahead and the layout picks what's on by its own clock (`environment.date` on iOS, `Date.now()` on Android): iOS gets the same props in a timeline entry at each class start and end, and Android's `UpNextProvider` (`res/xml/up_next_info.xml`) redraws every 30 minutes. Its classes are what the app last fetched, up to the end of next week. A class opens its course (`learnx://course/<id>`, when the class is tied to a course): the Lock Screen widget's one, and each class row of a medium or large one (`Link`); Android's rows use `openUrl`. The rest of the widget, and a small one, open `learnx://today`. Class times name the day only past today: "Tomorrow", the weekday within a week, the date from a week on; the Lock Screen and small widgets show the start alone where a range doesn't fit. Class rows read like deadline rows, the course first. A small widget lists the classes after the featured one as fit, in short, before falling back to the featured class alone in full.
