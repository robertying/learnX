# src/widgets

- The "Deadlines" home screen widget (iOS and Android) is built with `expo-widgets`. Its layouts are `src/widgets/DeadlinesIOS.tsx` (`@expo/ui/swift-ui`) and `src/widgets/DeadlinesAndroid.tsx` (`@expo/ui/jetpack-compose`, limited to what Glance supports). A function with the `'widget'` directive is turned into a string by the widgets Babel plugin (from babel-preset-expo) and runs in the widget runtime: no hooks, imports or outside values, only its props and `environment`. `src/widgets` is left out of the React Compiler.
- `updateDeadlineWidget` (`src/widgets`) is called by `helpers/surfaces` whenever the cached assignments, archives or hidden courses change (see "Surfaces" in the root `AGENTS.md`), and emptied on logout. On iOS it writes a timeline with an entry at each upcoming deadline, so due items drop off without the app; Android gets a snapshot of up to ten deadlines with preformatted due times; `DeadlinesProvider` redraws every 30 minutes (`res/xml/deadlines_info.xml`) and the layout leaves out the ones that have passed by `Date.now()`.
- Taps: each row carries a `learnx://assignment/<id>` link and the widget a `learnx://assignment` one (`getTargetUrl` in `helpers/openTarget.ts`). `useLinkTaps` opens them through the same path as notification taps (see "Navigation" in the root `AGENTS.md`); other `learnx://` links, like the share extension's, are ignored. iOS medium and large widgets wrap rows in `Link` and set `widgetURL` for the rest; small widgets have one tap target (the list) and the Lock Screen one opens the next assignment. Android rows use the `openUrl` modifier.
- We don't use prebuild, so the native setup the expo-widgets config plugin would generate is checked in: the `ExpoWidgetsTarget` extension (`ios/ExpoWidgetsTarget`, bundle id `io.robertying.learnX.Widgets`, app group `group.io.robertying.learnX`, iOS only, not on Mac Catalyst), its Podfile target, `ExpoWidgetsAppGroupIdentifier` in the app's Info.plist, and on Android `DeadlinesProvider`, its manifest receiver and `res/xml/deadlines_info.xml` / `res/values/expo_widgets.xml`. When upgrading expo-widgets, run its config plugin in a throwaway prebuild copy and compare. Adding a widget means a new Swift widget in `index.swift`, a provider on Android and an entry in `expo_widgets_names`.
- Android: the Gradle build embeds `DeadlinesAndroid.tsx` and its `initialProps` (listed in `android/app/src/main/expo-widgets-layout-registry.config.json`), so a widget added before the app has run shows "Open learnX to see deadlines" instead of expo-widgets' "No layout found". The layout the app stores at runtime wins over the embedded one. Gradle doesn't track the layout file as an input, so a layout change may need a clean build to update the embedded copy. Our `expo-widgets` patch makes tapping anywhere on the widget open the app, adds an `openUrl` modifier (`{ $type: 'openUrl', url }`, a Glance `actionStartActivity` for an `ACTION_VIEW` intent) for per-row links, and adds `environment.locale`, since the embedded props can't hold translated strings.
- The "Up Next" widget (`src/widgets/UpNextIOS.tsx`, `UpNextAndroid.tsx`, `updateUpNextWidget`) shows the class on now or next and the next deadlines. `helpers/surfaces` feeds it this week's and next week's classes from the cache (`getCachedWeekSessions` in `data/schedule`: Today's calendar or course-time fallback, without hidden courses); `useUpNext` (main UI) keeps those two weeks fetched. Its props hold all the classes still ahead and the layout picks what's on by its own clock (`environment.date` on iOS, `Date.now()` on Android): iOS gets the same props in a timeline entry at each class start and end and each deadline, and Android's `UpNextProvider` (`res/xml/up_next_info.xml`) redraws every 30 minutes. The background sync updates its deadlines; its classes are what the app last fetched, up to the end of next week. Tapping it opens `learnx://today`.
