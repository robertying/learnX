# AGENTS.md

learnX is a React Native app (iOS, iPadOS, Mac Catalyst, Android) for Tsinghua University's Web Learning, built on [`@robertying/thu-learn-lib`](https://github.com/robertying/thu-learn-lib). This file holds what applies everywhere. Folders with more to know have their own `AGENTS.md`, and the workflows are skills:

| `src/data/AGENTS.md`                  | Stores, TanStack Query, server actions and favorites, timetable, background sync, login and account data, mock login and mock data |
| `src/widgets/AGENTS.md`               | Home screen widgets (`expo-widgets`)                                                                                               |

## Commands

- `pnpm start` runs Metro; `pnpm ios` / `pnpm android` build and launch the app.
- `pnpm pod` runs `pod install` and `pod update` through Bundler, with the CocoaPods version locked in `Gemfile.lock` (run `bundle install` once first). Use the Ruby in `.ruby-version` with a gem folder you can write to, such as Homebrew's (`brew install ruby`, with `$(brew --prefix ruby)/bin` first on `PATH`); Bundler installs the gems there.
- `pnpm bump major|minor|patch` (or `pnpm bump x.y.z`) sets the app version in `package.json`, the Xcode project and Gradle and bumps the build number; `pnpm bump build` (or `pnpm bump` alone) is a rebuild (build number + 1). See the release skill.
- Run `pnpm format` (Oxfmt) after changing files; `pnpm typecheck` and `pnpm lint` (Oxlint, config in `.oxlintrc.json`) must pass before committing. Lint is type-aware (`oxlint-tsgolint`): mark an intentionally unawaited promise with `void`.
- User-visible text goes in `src/assets/translations` (`en.ts` and `zh.ts`), read with `t('key', { param })` from `helpers/i18n`; `{param}` placeholders are filled in, and date formats are translations too. The `learnx/no-han-outside-translations` lint rule (`lint/plugin.mjs`) rejects Chinese text elsewhere in `src`; disable it per line only for text that must not be translated, with the reason.
- Debug builds load JS from Metro; only native changes need a rebuild.
- `scripts/test-ios.sh <simulator udid>` runs the native iOS tests (Swift Testing) and prints the line coverage of the app's and the modules' Swift; see `modules/AGENTS.md`.
- `android/local.properties` (git-ignored, see `android/local.properties.example`) holds the Android release signing values; debug builds don't need it.
- `.env` (git-ignored, see `.env.example`) is inlined at build time into `helpers/env.ts` by `babel/inline-env.js`, which only passes listed keys: mock logins as is, the courseX token masked, and `LIVE_*` test logins in debug builds only. Add a key there before reading it in the app. The app can be used without a Tsinghua account through the mock login (`src/data/AGENTS.md`).

## React Compiler

- `babel-plugin-react-compiler` (in `babel.config.js`) memoizes every component and hook under `src/`, so don't add `useMemo`, `useCallback` or `React.memo` for performance.
- Don't make an effect depend on a function. A function that an effect only calls goes in `useEffectEvent`, and the effect lists the data it reacts to (e.g. `refresh` in `Notices`: `useEffect(() => refresh(), [courseIds, loggedIn])`). The compiler's memoization is an optimization, not a guarantee, so an effect shouldn't rerun just because a function fell out of compilation. `react-hooks/exhaustive-deps` flags the direct cases.
- `useCallback` / `useMemo` are still right where a value has to keep its identity and can't be an effect event: handlers handed to `navigation.setOptions` from an effect, functions and values in a context provider (the split views), and hook outputs that callers use as effect deps (`useFilteredData`).
- Show toasts with the module-level `toast()` from `components/Toast`, not through props or context.
- The compiler silently skips a function it can't handle and leaves it unmemoized. In 1.0 that includes `try` blocks with `finally`, `throw`, or conditional / logical / optional-chaining expressions (`?:`, `&&`, `||`, `??`, `?.`): compute values before the `try` and keep only the awaited calls inside it. Constants named `use…` are taken for hooks, so don't use that prefix for non-hooks.

## Navigation

- `App.tsx` only sets up the providers and picks login or main UI. The navigators are in `src/navigation/` (`stacks.tsx` for the tab and modal stacks, `DetailStack.tsx` for the split view's detail pane, `MainTab.tsx` with its `tabs` table, and `index.tsx` for the root), with shared header options in `navigation/options.tsx`. Split views: `NativeSplitView.tsx` (UISplitViewController, one per tab on iPad and iPhone), `SidebarSplitNavigator.tsx` (the Mac's sidebar of tabs) and `SplitView.tsx` (Android's, drawn in JS, plus the `SplitViewContext` all three provide). A stack lists the item detail screens it shows with `renderItemDetails([...])` and the settings screens with `renderSettingDetails()`; its param list is built from `ItemDetailParams` and `SettingDetailParams` in `screens/types.ts` to match. The colors and the navigation theme are in `src/theme/`. Startup work lives in hooks: `useStoresLoaded`, `useReLogin`, `useShareHandler` and `useMainStartup` (semester, courses, timetable, background sync, server actions and taps from outside the app once logged in). Android's update check is `hooks/useAvailableUpdate` (the TUNA mirror, compared with the installed app's native version, not `package.json`, which an over-the-air update can change).
- Taps from outside the app (notifications, widget rows and other `learnx://` links, Spotlight results) are opened by `useIncomingTargets` through `useOpenTarget`: it shows the item's list and sets the pending item (`setPendingTarget`), which the list opens with `usePendingTarget` (in its split view's detail pane when there is one). The target types and the `learnx://` links are in `helpers/openTarget`.
- Headers: each tab's first screen has a large title (`tabRootOptions` in `navigation/options.tsx`) on iPhone and iPad from iOS 26, where its subtitle (the filter, the date) is native; below iOS 26 the subtitle is our own `HeaderTitle`, which a large title would hide, so those keep the small title, as does the Mac. A large title collapses with the screen's first scroll view, so put anything above a list in its header (`SyncStatus` in `FilterList`) or a `Form`'s first section (`SyncStatusSection` on Today); a view above it also sits behind the transparent header. From iOS 26 on iPhone and iPad every stack's header is transparent and its back button the chevron alone (`stackScreenOptions`), as SwiftUI shows it (on iOS 27 a titled one fades out and in after a push in which header buttons morph, in plain UIKit too), so every screen is laid out under the header and scrolls under its glass: a scroll view keeps clear of the header itself (`contentInsetAdjustmentBehavior="automatic"`, which our `FlatList`, `ScrollView`, `Form` and the web views have), and a view over the top of the content keeps clear of the header with react-native-screens' `SafeAreaView` top edge (`PageProgressBar`, Course detail's floating tabs). The header blurs what scrolls under it only for the screen's first scroll view, so Course detail shows its selected list alone there, with no pager. That blur is the soft scroll edge effect: UIKit's automatic style is the hard one (an opaque band with a line) in an iPad split view's columns other than the first, so `ios/learnX/ScrollEdgeEffect.swift` gives every UIKit scroll view the soft one and `Form` sets it for SwiftUI's (not on Mac). Don't set `headerTransparent` or `headerStyle` per screen (a test checks the stacks). Before iOS 26 the header takes a `Form`'s gray.
- The app opens on the Today tab (`screens/Today.tsx`): one Classes section with the class on now and the next one (when each ends or starts in the row's `overline`, so the course name keeps the row's width) and a Schedule row (`screens/Schedule.tsx`: the next seven days' classes by day, in the split view's detail pane where there is one), what's due today and tomorrow, and counts of unread notices and new files, each opening its tab on the Unread filter. The whole day's classes stay off Today so a busy day doesn't push the rest off screen. Settings opens from Today's header (it's in `TodayStack`), except on Mac, where it keeps its sidebar item: Android's navigation bar holds at most five tabs and iPhone moves a sixth into "More". ⌘, opens it either way (`useMainCommands`).
- First launch and updates: a new install (`data/install`: no install mark, no legacy import mark, no 18.0.x data) first drops a login the iOS keychain kept from before the app was deleted, then opens on `screens/Welcome` (the login stack's first screen until `welcomeSeen`). Once the main UI shows, `hooks/useLaunchSheet` opens one sheet: `screens/Setup` (notifications, deadline reminders, calendar sync) after the first login, or What's New (`WhatsNewStack`) for the newest release in `helpers/whatsNew` since `whatsNewSeenVersion`, unless the app was opened from a notification, widget, link or Spotlight. Releases are keyed by `package.json`'s version, which over-the-air updates change too; a row with `minNative` is left out until the installed app has that native version. Both pages draw `components/FeatureList`, and Settings › What's New reopens the sheet.
- Lists open an item with `useShowDetail` (`hooks/useDetailNavigator`): beside the list in a split view's detail pane, which starts over with the item, or pushed on the list otherwise. A screen that stacks something on its item in the pane (an attachment, a submission) uses `useDetailNavigator().push`. The Notices, Assignments and Files tabs share `hooks/useContentList` (filters, refresh, pull to refresh, opening items and pending targets).
- Detail screens (notice, assignment, file, course, assignment submission) take `{ id }` params and read the item from the query cache, so they stay current after a refresh: pass the id, never the item. An item missing from the semester being shown is looked up in the other semesters' cached lists, so a detail screen left open survives a semester switch. They show `components/NotFound` when the item is gone and set their header title with `hooks/useHeaderTitle`. Notice and assignment attachments are not in the cache and open `FileDetail` with `{ attachment }`.

## Surfaces

- `helpers/surfaces` keeps what learnX shows outside the app in step with its data: the Deadlines and Up Next widgets, deadline reminders, Spotlight, the App Intents' data, and the assignments written to the system calendar or Reminders. `watchSurfaces()` (from `index.js`, so it runs in every JS runtime: the app, the background task and Android's notification action task) follows the cached assignments, notices, courses and timetable, the user data and the settings, and `refreshSurfaces()` updates each output whose inputs changed (compared like an effect's dependencies), one run at a time. Code the system may stop soon after (the background sync, notification actions) awaits `refreshSurfaces()`; logout calls `clearSurfaces()`.
- Don't call the widget, Spotlight, reminder or calendar functions from screens or hooks: change the data and the surfaces follow. A failed calendar write reaches the app through `subscribeSurfaceErrors` (shown as a toast). To add an output, add an entry to `surfaces` with its dependencies and update function.

## Downloads

- Downloaded files are the app's own and kept by ids, never names: `<Caches>/downloads/<course id>/<file id>/<title>.<ext>` (`helpers/files/downloads`), with a `course.json` beside each course's files (its names and semester) for when the course isn't cached. Course names follow the app's language, so a path built from one would break after a language change. People get files out through Downloads › Export (`helpers/files/export`): a folder they pick with the system picker (on Mac too, with the user-selected read-write entitlement) gets `learnX/<semester>/<course>/<title>.<ext>` in the app's language. Sharing, opening and the Mac's Save to Downloads name a file by its title alone. The app's Documents folder isn't shown in Files or Finder (no `UIFileSharingEnabled`): it holds the app's databases, not files for people.

## UI components

- The app has its own small component layer in `src/components`; there is no UI kit. Space things with the scale in `constants/Spacing` and lay a group out with `gap` rather than a margin on each child, so neighbors' margins never add up. Colors come from `useTheme()` in `src/theme` (`theme.colors`, `theme.dark`), with `onSurfaceHigh` and `onSurfaceMedium` as the title/body and caption text colors (iOS's `label` and `secondaryLabel`, Material 3's `onSurface` and `onSurfaceVariant`).
- Text uses `Text`, `Title`, `Headline`, `Paragraph` and `Caption` from `components/Text`, which draw the platform's own text styles: Apple's Dynamic Type styles on iOS, iPadOS and Mac (with `dynamicTypeRamp`, so each scales along its own curve) and the Material 3 type scale on Android. Pick a style with `variant` (`title`, `headline`, `body`, `subheadline`, `label`, `footnote`, `caption`) instead of setting `fontSize`; `textStyles` has the same styles for text `Text` doesn't draw, like a `TextInput`. Also there: `Divider`, `ProgressBar`, `Badge`, `IconButton` (a SwiftUI button with an SF Symbol on iOS and Mac, a Compose icon button with a Material Symbol from `src/assets/icons` on Android; add a name to `IconButtonIcon` and both maps for a new icon), `SystemIcon` (any icon React Native draws itself, in rows, empty states, swipe actions and menus: a name from `helpers/systemIcons`, which maps it to an SF Symbol drawn natively by expo-symbols on iOS and Mac and to a Material Symbol from expo-symbols' font on Android; add a new icon there with both names and, for Android, its codepoint, which a test checks), `Touchable` (ripple on Android), `LoginFields` (the login's account and password: a SwiftUI `TextField` and `SecureField` with their `textContentType` in one host on iOS and Mac, which password AutoFill needs to offer saving them, and Compose outlined fields with an Autofill `contentType` on Android), `ContainedButton` and `Toast` (shown with the module-level `toast()`: a glass pill at the bottom of the window (above the iPhone tab bar and the keyboard) on iOS, iPadOS and Mac, drawn in a `FullWindowOverlay` so it shows over modals; the system `ToastAndroid` on Android).
- Deadlines follow one rule everywhere (cards, details, Today, widgets): `deadlineUrgency` in `helpers/assignments` is `urgent` (red) under a day left, which `deadlineText` counts in hours, and `soon` (orange) when it's due by the end of tomorrow, which it counts as "1 day" (days are calendar days). Passed deadlines and submitted assignments get no color. Cards draw it as a pill, other places as the detail text in the same hue (`deadlineTone`); the brand color never marks a deadline. The other status colors follow the same meanings: red for a favorite's heart, badges and destructive actions, orange for the important flag and a late submission, green for submitted; the brand color is for unread dots, grades, counts and form row icons, never a state. A detail page's status row shows its state by its icon (done, submitted late, late submission open, missed), not by a color.
- `helpers/systemIcons` names every icon in the app by meaning, so a meaning has one icon wherever it shows (a tab, a course card's counts, an empty list, a form row): reuse its entry instead of picking a symbol for one screen. The tabs (`navigation/MainTab`) draw theirs filled on the iOS tab bar and as the outline in the Mac sidebar; Android's navigation bar loads them as vector drawables, `tab_<symbol>` and `tab_<symbol>_filled` for the selected tab, in `android/app/src/main/res/drawable` (paths from the Material Symbols font, 400 weight). Today's icon follows the time of day (`useDayPart`, `helpers/dayPart`). An empty list shows its section's icon and "No Notices", "No Files", … (`components/Empty`).
- List cards hand `CardWrapper` a spoken `accessibilityLabel` built with `cardAccessibilityLabel` (`components/CardRow`): the title first, then whose and when, then every state the row shows only visually (unread dot or bold title, flag, paperclip, answer key), then a shortened preview. A new glyph or state goes in that label too. Swipe, long-press and drag actions are also `accessibilityActions` (course reorder offers Move Up / Move Down). `TextField` gives its `label` to the input as its accessibility label.
- Native controls come from `@expo/ui`: `components/TextButton` (a borderless SwiftUI `Button` on iOS and Mac, the Material 3 text button on Android; `fill` for file names that shorten to one line), `components/Switch`, `components/SelectionMark` (SF Symbol circles on iOS and Mac, the Material checkbox on Android; display only), the Android card long-press menu (`components/CardMenu.android.tsx`, a Compose dropdown menu) and `components/DateRangePicker` (two SwiftUI date pickers in a sheet on iOS and Mac, Material's range picker dialog on Android). Search uses the native header search bar (`headerSearchBarOptions`), and choice sheets use `ActionSheetIOS` / `Alert`.
- Settings-style screens and the notice and assignment detail pages use `components/Form`: a SwiftUI `Form` (inset grouped sections, SF Symbols, native toggles and chevrons) on iOS, iPadOS and Mac, and the Material 3 grouped list (Compose `ListItem`s, Material Symbols) on Android. Build them from `FormSection` (title, footer caption) with `FormLink`, `FormButton` (`destructive`, `loading`, `disabled`, `selected` for a choice list), `FormToggle`, `FormNumberField`, `FormFile` (a file that opens on tap; `struck` when it is being replaced), `FormTextField` (full-width text, `multiline` grows from six lines; it keeps typed text itself and takes a new `value` only when it differs from what it reported, with `format` to clean what is typed) `FormProgress`, `FormText` (`detailTint` `accent` for a grade, `red` / `orange` for a deadline by `deadlineTone`), `FormTitle` (a detail page's title and subtitle, as in Calendar's event details); text and link rows take an `overline`, a short accent-colored line above the title (Material's overline, a caption on iOS and Mac) and `FormView` (a React Native view hosted in a row and sized by its content, such as the HTML body in `AutoHeightWebView`) rows, each with an `icon` (a `helpers/systemIcons` name) where it has one. A row component of your own (like AssignmentDetail's excellent homework row) must pass on the `position` prop it is given. Keep all of a form's look in `components/Form*.tsx`: screens only compose rows. Rows must be direct children of their section (fragments and conditionals are fine): on Android the section rounds each row by its position. The form scrolls by itself, so don't wrap it in a `ScrollView` or `KeyboardAvoidingView`.
- An `@expo/ui` view that exists on only one platform goes in a `.android.tsx` / `.ios.tsx` file, since `@expo/ui/jetpack-compose` and `@expo/ui/swift-ui` look up their native views when imported. Props both files share go in `X.shared.ts` (an `.android.tsx` can't value-import from `./X`: Metro resolves that to itself).
- Host native views in `components/ThemedHost` rather than `@expo/ui`'s `Host`: it seeds the palette from the theme's primary color, and on Android adds the app's Compose color roles (`useComposeColorOverrides`).

## Unit tests (Jest)

- Pure logic lives in `src/helpers` and is tested in `src/helpers/__tests__`. Hooks are tested in `src/hooks/__tests__` with `renderHook` from `@testing-library/react-native` (v14: `renderHook`, `rerender` and `act` are async, so await them).
- Mock native modules and the data layer per test file (`jest.mock('helpers/files/downloads', …)`, `components/Toast`, pickers, `data/source`); use the real Zustand stores (`setSetting`, `setPendingAssignmentData`, `resetUserData`) instead of mocking them. Tests of `helpers/files` opt into an in-memory file system (`jest/mocks/memoryFileSystem.ts`) that they seed and read back; `helpers/html` loads with `data/source` mocked. Global mocks are listed in `jest/setup.ts`, each stand-in in `jest/mocks/`, and Jest clears every mock's calls between tests (`clearMocks`).
- Test hooks that hold real logic (state, ordering, error paths), not thin wrappers around one call.
- Components and screens are tested in `src/components/__tests__` and `src/screens/__tests__` with `render` and `screen` (also async in v14). Query what the user sees (text, role, `testID`); press through `userEvent` (`userEvent.setup({ advanceTimers: jest.advanceTimersByTime })` under fake timers), since `fireEvent.press` can bubble to the test element's own `onPress` prop. Screens get a plain `navigation` object of `jest.fn()`s and mock their data hooks (`data/content`).
- `pnpm test` runs two Jest projects (`jest.config.js`): `ios` loads each split component's iOS file, and `android` runs the tests in `__tests__/android/` with the `.android.tsx` files, `Platform.OS` 'android' and Compose stand-ins (`jest/mocks/expoCompose.tsx`, `jest/mocks/expoComposeModifiers.ts`): a row made tappable by `clickable`, `toggleable` or `selectable` is a pressable with that role and state, and a dropdown shows its items only while expanded. Test an Android variant there.
- `jest/setup.ts` replaces native views globally: `@expo/ui` `Icon` renders a view with testID `icon-<name>`, and expo-symbols' `SymbolView` a view with the testID `SystemIcon` is given; `@expo/ui` `Button` and `Switch` are a pressable and an accessible `switch` (flip it with `fireEvent(switch, 'valueChange', value)`); `ReanimatedSwipeable` renders its children and gives its ref `mockSwipeableMethods` (`jest/mocks/swipeable.tsx`); every `@expo/ui/swift-ui/modifiers` export is a `jest.fn`. Reanimated runs its web build through its Jest resolver; haptics, device info, cookies, the share extension and safe area insets are mocked. dayjs has `relativeTime` and the `zh-cn` locale loaded, as in `App.tsx`.
