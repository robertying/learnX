## Commands

- `pnpm start` runs Metro; `pnpm ios` / `pnpm android` build and launch the app.
- `cd ios && bundle exec pod install` installs the pods with the CocoaPods version locked in `Gemfile.lock` (run `bundle install` once first); run it after `ios/Podfile`, a native package or a patch changes. `pnpm pod` also runs `pod update`, which moves pods to newer versions: use it only when upgrading (the upgrade-dependencies skill). Use the Ruby in `.ruby-version` with a gem folder you can write to, such as Homebrew's (`brew install ruby`, with `$(brew --prefix ruby)/bin` first on `PATH`); Bundler installs the gems there.
- `pnpm bump major|minor|patch` (or `pnpm bump x.y.z`) sets the app version in `package.json`, the Xcode project and Gradle and bumps the build number; `pnpm bump build` (or `pnpm bump` alone) is a rebuild (build number + 1). See the release skill.
- Run `pnpm format` (Oxfmt) after changing files; `pnpm check` (typecheck, lint, format check, Jest with coverage, ShellCheck: what CI's JS checks run, besides `scripts/check-release-bundle.sh`) must pass before committing. Oxlint's config is in `.oxlintrc.json`. Lint is type-aware (`oxlint-tsgolint`): mark an intentionally unawaited promise with `void`.
- User-visible text goes in `src/assets/translations` (`en.ts` and `zh.ts`; wording rules in its `AGENTS.md`), read with `t('key', { param })` from `helpers/i18n`; `{param}` placeholders are filled in, and date formats are translations too. The `learnx/no-han-outside-translations` lint rule (`lint/plugin.mjs`) rejects Chinese text elsewhere in `src`; disable it per line only for text that must not be translated, with the reason.
- Debug builds load JS from Metro; only native changes need a rebuild.
- `scripts/test-ios.sh <simulator udid>` runs the native iOS tests (Swift Testing) and prints the line coverage of the app's and the modules' Swift; see `modules/AGENTS.md`.
- `android/local.properties` (git-ignored, see `android/local.properties.example`) holds the Android release signing values; debug builds don't need it.
- `.env` (git-ignored, see `.env.example`) is inlined at build time into `helpers/env.ts` by `babel/inline-env.js`, which only passes listed keys: mock logins as is, the courseX token masked, and `LIVE_*` test logins in debug builds only. Add a key there before reading it in the app. The app can be used without a Tsinghua account through the mock login (`src/data/AGENTS.md`).

## React Compiler

- `babel-plugin-react-compiler` (in `babel.config.js`) memoizes every component and hook under `src/`, so don't add `useMemo`, `useCallback` or `React.memo` for performance.
- Don't make an effect depend on a function. A function that an effect only calls goes in `useEffectEvent`, and the effect lists the data it reacts to (e.g. `refresh` in `Notices`: `useEffect(() => refresh(), [courseIds, loggedIn])`). The compiler's memoization is an optimization, not a guarantee, so an effect shouldn't rerun just because a function fell out of compilation. `react-hooks/exhaustive-deps` flags the direct cases.
- `useCallback` / `useMemo` are still right where a value has to keep its identity and can't be an effect event: handlers handed to `navigation.setOptions` from an effect, functions and values in a context provider (the split views), and hook outputs that callers use as effect deps (`useFilteredData`).
- Show toasts with the module-level `toast()` from `components/Toast`, not through props or context.
- The compiler silently skips a function it can't handle and leaves it unmemoized. In 1.0 that includes `try` blocks with `finally`, `throw`, or conditional / logical / optional-chaining expressions (`?:`, `&&`, `||`, `??`, `?.`): compute values before the `try` and keep only the awaited calls inside it. Constants named `use…` are taken for hooks, so don't use that prefix for non-hooks.

## Surfaces

- `services/surfaces` keeps what learnX shows outside the app in step with its data: the Deadlines and Up Next widgets, deadline and class reminders, Spotlight, the App Intents' data, the assignments written to the system calendar or Reminders, and the courses shared with courseX (Settings › Course Information Sharing). `watchSurfaces()` (from `index.js`, so it runs in every JS runtime: the app, the background task and Android's notification action task) follows the cached assignments, notices, courses and timetable, the user data and the settings, and `refreshSurfaces()` updates each output whose inputs changed (compared like an effect's dependencies), one run at a time. Code the system may stop soon after (the background sync, notification actions) awaits `refreshSurfaces()`; logout calls `clearSurfaces()`.
- Don't call the widget, Spotlight, reminder, calendar or courseX functions from screens or hooks: change the data and the surfaces follow. A failed calendar write reaches the app through `subscribeSurfaceErrors` (shown as a toast). To add an output, add an entry to `surfaces` with its dependencies and update function.

## Downloads

- Downloaded files are the app's own and kept by ids, never names: `<Caches>/downloads/<course id>/<file id>/<title>.<ext>` (`services/files/downloads`), with a `course.json` beside each course's files (its names and semester) for when the course isn't cached. Course names follow the app's language, so a path built from one would break after a language change. People get files out through Downloads › Export (`services/files/export`): a folder they pick with the system picker (on Mac too, with the user-selected read-write entitlement) gets `learnX/<semester>/<course>/<title>.<ext>` in the app's language. Sharing, opening and the Mac's Save to Downloads name a file by its title alone. The app's Documents folder isn't shown in Files or Finder (no `UIFileSharingEnabled`): it holds the app's databases, not files for people.

## Unit tests (Jest)

- `src/helpers` holds logic with no side effects beyond thin platform reads (i18n, icons, what's new), tested in `src/helpers/__tests__` without mocks of the server or the system. Code that talks to the system's stores and outputs or to a server outside `data/source` (background sync, notifications, reminders, Spotlight and App Intents, widgets' feed in `services/surfaces`, the calendar in `services/calendar`, downloaded files in `services/files`, crash reporting, courseX, submissions, store report, launch options, list actions) lives in `src/services`, tested in `src/services/**/__tests__`. The calendar's pure builders are in `helpers/calendar` (event details, ICS). Hooks are tested in `src/hooks/__tests__` with `renderHook` from `@testing-library/react-native` (v14: `renderHook`, `rerender` and `act` are async, so await them).
- Mock native modules and the data layer per test file (`jest.mock('services/files/downloads', …)`, `components/Toast`, pickers, `data/source`); use the real Zustand stores (`setSetting`, `setPendingAssignmentData`, `resetUserData`) instead of mocking them. Tests of `services/files` opt into an in-memory file system (`jest/mocks/memoryFileSystem.ts`) that they seed and read back; `helpers/html` loads with `data/source` mocked. Global mocks are listed in `jest/setup.ts`, each stand-in in `jest/mocks/`. After each test Jest clears every mock's calls (`clearMocks`) and restores spies and replaced properties (`restoreMocks`), so switch platforms with `jest.replaceProperty(Platform, 'OS', 'android')` and don't restore by hand.
- A test fails on any `console.error` or `console.warn` it doesn't expect (`jest/setupAfterEnv.ts`), such as an act() warning: change a store that a rendered component reads (`useAuthStore.setState`, `setCurrentSemester`, `setSetting`) inside `await act(...)`, in `afterEach` too. A test that expects a log spies on it (`jest.spyOn(console, 'warn').mockImplementation(() => {})`). TanStack Query's notifications already run in act().
- Test hooks that hold real logic (state, ordering, error paths), not thin wrappers around one call.
- Components and screens are tested in `src/components/__tests__` and `src/screens/__tests__` with `render` and `screen` (also async in v14), one file per component or screen named after it (`CardRow.test.tsx`, and `android/CardRow.test.tsx` for its Android file); shared test data goes in `jest/fixtures/`. Tests import from `jest/` as `test-utils/…` (`test-utils/fixtures/cards`, `test-utils/mocks/navigator`), an alias in `babel.config.js` and `tsconfig.json`, never by a relative path. Query what the user sees (text, role, `testID`); press through `userEvent` (`userEvent.setup({ advanceTimers: jest.advanceTimersByTime })` under fake timers), since `fireEvent.press` can bubble to the test element's own `onPress` prop. Screens get their props from `screenProps({ navigation, route: { params } })` (`test-utils/screenProps`), with `navigation` a plain object of the `jest.fn()`s the screen calls, and mock their data hooks (`data/content`).
- `pnpm test` runs three Jest projects (`jest.config.js`): `ios` loads each split component's iOS file, `tooling` runs the tests of the repo's own tooling in `scripts/__tests__` (the E2E env values and posture links, the Maestro flow references, the lint plugin) with Node's types (`scripts/tsconfig.json`, which `pnpm typecheck` also checks, with the config files, `babel/`, `lint/` and the scripts as checked JS), and `android` runs the tests in `__tests__/android/` with the `.android.tsx` files, `Platform.OS` 'android' and Compose stand-ins (`jest/mocks/expoCompose.tsx`, `jest/mocks/expoComposeModifiers.ts`): a row made tappable by `clickable`, `toggleable` or `selectable` is a pressable with that role and state, and a dropdown shows its items only while expanded. Test an Android variant there.
- CI runs `pnpm test --coverage`, which fails when coverage drops below `coverageThreshold` in `jest.config.js` (kept just under the current numbers). Cover new code with tests, and raise the thresholds when coverage grows.
- `jest/setup.ts` replaces native views globally: `@expo/ui` `Icon` renders a view with testID `icon-<name>`, and expo-symbols' `SymbolView` a view with the testID `SystemIcon` is given; `@expo/ui` `Button` and `Switch` are a pressable and an accessible `switch` (flip it with `fireEvent(switch, 'valueChange', value)`); `ReanimatedSwipeable` renders its children and both sides' actions, puts `enabled` and its swipe callbacks on its props for tests to call, and gives its ref `mockSwipeableMethods` (`jest/mocks/swipeable.tsx`); every `@expo/ui/swift-ui/modifiers` export is a `jest.fn`. Reanimated runs its web build through its Jest resolver; haptics, device info, cookies, the share extension and safe area insets are mocked. dayjs has `relativeTime` and the `zh-cn` locale loaded, as `helpers/i18n` sets them up.

## Pull requests

- One change per pull request, squash-merged once the required checks (`CI / JS checks`, `CI / Android unit tests`) pass. The title and description say what the change does compared with `main` and why, for a reader who hasn't seen how it came about: no history of earlier attempts or review rounds. The squash commit message follows the same rule.
