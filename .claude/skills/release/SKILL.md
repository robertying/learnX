# Releasing learnX

- [fastlane](https://docs.fastlane.tools) (`fastlane/Fastfile`) builds and uploads releases on a Mac. It and CocoaPods are in the `Gemfile`: run `bundle install` once (the Ruby in `.ruby-version`, e.g. Homebrew's), then `pnpm install` and `cd ios && bundle exec pod install` (the locked CocoaPods and `Podfile.lock`; not `pnpm pod`, which also updates pods) before building.
- A feature release gets What's New highlights before it's built: an entry for its version at the top of `releases` in `src/helpers/whatsNew.ts` (3 or 4 rows, strings in `en.ts` / `zh.ts`, `minNative` on rows that need the new native code). A bug-fix release gets none and shows only the Changelog badge.
- `pnpm bump major|minor|patch` or `pnpm bump x.y.z` (`bundle exec fastlane bump version:x.y.z`) sets the version in `package.json`, the Xcode project and `android/app/build.gradle`. The build number goes to the next multiple of 10 (18.0.3 is 4530), or up by 1 for a rebuild of the same version (`pnpm bump build`, or `pnpm bump` alone); the Android versionCode is 9200000 + the build number.
- If the release changes native code since the last one, also set the over-the-air runtime version in `app.json` to the new version and record it in `ota-fingerprint.json` (CI's "Runtime version" check says when, and prints the values; "Over-the-air updates" in `AGENTS.md`). A JS-only release keeps it. The build lanes refuse to build without `OTA_UPDATE_URL` and `EXPO_PROJECT_ID` in `.env`.
- `bundle exec fastlane <ios|mac|android> build` builds into `build/release/v<version>/` without uploading anything: the .ipa, the Mac Catalyst .pkg, the AAB, the APKs renamed `learnX-<abi>-v<version>.apk` with `latest.json` (what the in-app updater reads from the TUNA mirror), and the JS source map of each build in `sourcemaps/`. Crashlytics doesn't symbolicate JS, so keep these maps for `metro-symbolicate`. The Android build also uploads native symbols to Crashlytics. `bundle exec fastlane android install_bundle` then installs that AAB on the connected device through `bundletool` (`brew install bundletool`), split the way Google Play splits it.
- `<platform> release` builds and uploads; `bundle exec fastlane release notes:<file>` builds all three, then uploads to App Store Connect (not submitted for review), to Google Play as a draft on `track:` (default `production`), and creates a draft GitHub release `v<version>` at HEAD with the APKs, `latest.json` and a zip of the source maps. Release lanes need a clean git tree. Notes come from the release-notes skill: `bundle exec fastlane notes` (after `bump`) runs it through `claude -p` with read-only git/gh tools and saves `build/release/v<version>/release-notes.md`, which the release lanes use when no `notes:` is given, so review and edit it first. It refuses a version that's already tagged. Without the `claude` CLI (or logged out, or with `claude:false`) it writes a draft with the commits since the last tag and `TODO(release-notes)` placeholders, and the release lanes won't upload notes that still have one. A release lane run in a terminal with no notes file writes them first and asks before building.
- The build lanes need the repo-root `.env` with the mock login (`DUMMY_USERNAME`, `DUMMY_PASSWORD`; `babel/inline-env.js` inlines it), and fail before building without it; a worktree has none, so copy it from the main checkout. After building they check that each JS bundle has the mock login and no other `.env` value.
- Secrets go in `fastlane/.env` (git-ignored; fastlane loads it): `APP_STORE_CONNECT_API_KEY_KEY_ID`, `APP_STORE_CONNECT_API_KEY_ISSUER_ID`, `APP_STORE_CONNECT_API_KEY_KEY_FILEPATH` (.p8) for App Store Connect and Xcode signing (without them fastlane asks for an Apple ID), `GOOGLE_PLAY_CONSOLE_JSON_KEY` (path to the Play service account JSON; `SUPPLY_JSON_KEY` works too), and optionally `GITHUB_TOKEN` (otherwise `gh auth token`). Android signing reads `LEARNX_RELEASE_*` from `android/local.properties` (copy `android/local.properties.example`) and `android/app/release.keystore`.
- Don't upload, submit or publish anything unless asked; `build` lanes are safe to run.
